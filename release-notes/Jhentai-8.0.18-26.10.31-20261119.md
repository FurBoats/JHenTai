基于 JHenTai 8.0.18（原作者 JTMonster）+ 内置 Xray 核心 LibXray 26.10.31。

## 本版说明

与上一版（xray-v8.0.18-20261117-4）代码相同，本版主要是发布规范调整：

- Release 版本号改为 `Jhentai-<JH版本>-<Xray版本>-<构建日期>` 规范
- 新增 **universal APK**（全架构通用包），另继续提供 arm64-v8a / armeabi-v7a / x86_64 分架构包
- README 改版：只保留原作者署名与本仓库的改动说明
- 补齐此前各版本未写的变更记录（见下方补录）

## 补录：内置 Xray 以来的全部改动

### 首版（2026-11-17）

- 内置 Xray 核心（LibXray 26.10.31），应用内直接导入节点/订阅，不需要另外开代理软件；支持 vless / vmess / trojan / shadowsocks / socks / hysteria2
- 双节点分流：主节点（127.0.0.1:28780）承载全部流量；igneous 刷新专用节点（127.0.0.1:28781）只用来刷新 E-Hentai 的 igneous cookie，无直连兜底

### 第二版（2026-11-17）

- WebView 跟随应用的代理设置
- 修改 Xray 配置时先停核心再测试，避免测试接口在核心运行时被拒绝
- Hysteria2 证书锁定修复：订阅的 `pinSHA256` 转换为核心接受的 `pinnedPeerCertSha256` 注入
- 订阅拉取支持多 User-Agent / 多渠道，兼容 Clash YAML
- 订阅改为一等对象：分组显示 + 定时自动更新
- 主节点健康检查与按顺序回退
- Sad Panda 初版自动处理：自动刷新 igneous 并重试一次

### 第三版（2026-11-17）

- 订阅正文 base64 解码改由桥接层在本地完成（整包与逐行两种形式），修复制订阅读不出节点的问题

### 第四版（2026-11-17）

- Sad Panda 重做：在 EX 站点遇到空白响应即强制刷新 igneous 并重载原请求，去掉节流限制，并发触发共享一次刷新，带 toast 提示
- 冷启动优化：先启动 Xray 核心、等本地代理端口就绪后再加载界面，修首屏连接被拒

### 下载走代理（源码确认）

- 画廊图片下载与归档下载都走主节点代理；igneous 专用节点不参与下载
